# Подготовка проекта после клонирования

1. Прочитай AGENTS.md, README.md и package.json. Проверь `git status --short`, сохрани изменения пользователя. Запускай команды из корня текущего клона; не используй пути чужого компьютера.
2. Проверь `node --version` и `npm --version`: нужен Node.js 22.12+ и npm. Выполни `npm ci` с существующим package-lock.json. Если установка заблокирована средой или сетью, сообщи конкретную причину.
3. Только если .env отсутствует, скопируй .env.example в .env. Существующий файл не перезаписывай. Пользователь заполняет WCL_CLIENT_ID и WCL_CLIENT_SECRET локально через регистрацию клиента на https://www.warcraftlogs.com/api/clients/. Не выводи секреты, содержимое .env или токены и не проси их в чат. Без credentials доступны локальные архивы и проверки.
4. Выполни `npm run build` и `npm test`, сообщи результаты. Синтетические тесты не подтверждают живую интеграцию.
5. Подключение MCP описано в README. Подставляй абсолютный путь текущего клона к dist/index.js и доступный приложению Node.js. Конфигурацию пользователя меняй по его запросу, сохраняя существующие настройки. После подключения проверь наличие local_analysis в новом чате. Если инструмент недоступен, используй `node dist/cli.js '<JSON>'` с теми же параметрами и обозначь этот способ.
6. Реальную проверку API начинай с action=list для отчёта пользователя, затем определяй точные fight/actor ID и скачивай выбранные бои по AGENTS.md. Не запускай загрузки случайных отчётов из примеров ради установки. Интеграция проверена только после реального запроса API.

## Подготовка к публикации в Git

- Проверь исключение .env, data/, токенов, node_modules/ и dist/ из Git. В .env.example допускаются только пустые значения и безопасные примеры.
- Включай исходники, lockfile, синтетические тесты, инструкции и шаблон отчёта. Пользовательские HTML-отчёты с данными логов не добавляй автоматически.
- Если секреты или архивы уже отслеживаются Git, .gitignore недостаточно: сообщи об этом без вывода содержимого. Не переписывай историю самостоятельно.
- Не выдумывай URL нового remote. Подготовка клона сама по себе не означает разрешение на публикацию или push.

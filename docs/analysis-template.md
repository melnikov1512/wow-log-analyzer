# Сравнение Arcane Mage

## Контекст
Мой report/fight/actor: …; референс report/fight/actor: …
Источник данных: manifest.json, complete, pages/events, warnings, дата загрузки.
Босс/сложность/kill, длительность, patch/build (или недоступно), gameVersion/дата.
Таланты, hero talents, gear/stats, цели, внешние усиления, обязанности: факты либо «недоступно».

## Подтверждённые отличия
| Наблюдение | Мой таймкод / spell ID | Референс: таймкод / spell ID | Доказательство |
|---|---|---|---|
| … | … | … | report/fight + окно local_analysis + raw page |

Опенер, завершённые касты, КД, бурст, бафы/стаки, ресурсы, входящие события, смерти, цели/фазы.
Привязка каждого окна: начало бурста или фаза. В HTML показывай таймкоды мм:сс (или чч:мм:сс), смещения окна и длительности — в секундах без миллисекунд. Для таймкодов отбрасывай доли секунды, сохраняя исходный порядок событий. Точные timestamp и границы запросов остаются в данных; сырые JSON с миллисекундами в отчёт не вставляй.
Отсутствие события при неполном архиве — неизвестно.

## Возможные причины
Для каждой гипотезы: подтверждённые свидетельства, альтернативы (механика, цели, haste/GCD, запись), уверенность, что ещё проверить.
Не называй промежуток между кастами доказанным простоем; не называй отличие ошибкой без контекста.
Ротационные источники: URL, патч/билд, дата проверки. Несовпадение патча ограничивает выводы.

## Следующий рейд
1. Действие …; как проверить в следующем логе …
2. Действие …; как проверить …
3. При необходимости …

Не оценивать «точно потерянный DPS» без обоснованной модели и допущений.

## Обязательные разделы сравнения

### Использование бурстов
Сопоставь опенер и последующие окна: время и число использований КД, сочетание усилений, завершённые касты, бафы/стаки, ресурсы и доступность целей. Покажи обе стороны, подтверждённые отличия с таймкодами и ограничения. Задержка КД сама по себе не доказывает ошибку.

### Качество ротации вне бурстов
Определи исключаемые бурстовые окна каждой стороны по событиям и проверенным правилам специализации. Сравни сопоставимые оставшиеся окна: последовательности завершённых кастов, использование проков/ресурсов и поддержание эффектов, если данные доступны. Учитывай длину окон, цели и механику; сырые количества в окнах разной длины не являются оценкой качества. Если границы или события недоступны, укажи это вместо оценки.

Оба раздела входят в подтверждённые отличия до возможных причин и действий на следующий рейд. Для каждого используй таблицу доказательств выше.

## Формат HTML и иконки

Сохраняй итог в .html с UTF-8, lang="ru", встроенными стилями, читаемыми таблицами и адаптацией к узкому экрану. Дай ссылку на файл. Просмотр не должен требовать сервер или сборку приложения. Экранируй имена и другие данные логов при вставке в HTML.

Способность показывай как иконку 24–32 px + название + spell ID со ссылкой на Wowhead соответствующей версии игры. Используй проверенный abilityGameID/ability.guid; внутренний ID справочника отчёта не подменяет spell ID.

URL иконки проверяй по метаданным способности или странице Wowhead нужной версии игры; не угадывай имя файла. Локальный архив может не содержать иконок — проверь внешний источник отдельно. При недоступности картинки оставляй читаемые название/ID и явно отмечай отсутствие иконки. Добавляй alt, сохраняй читаемость текста при ошибке загрузки, указывай источник иконок и необходимость сети для внешних изображений. Иконки не заменяют доказательства; внешние tooltip-скрипты не обязательны.
